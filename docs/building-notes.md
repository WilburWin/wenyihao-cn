# 建站经验

## 先有内容，再决定页面密度

建站初期希望同时承载照片、学术、项目、视频和游戏，但内容数量不足时，堆叠卡片和复杂首页只会放大空白。后来把首页收成背景、姓名、简介和图标入口，把内容放到独立板块，维护起来更清楚。论文尚无内容时不造示例，B站采用主页入口，GitHub 则读取真实仓库。

不同板块可以有不同风格，但导航位置、尺寸、顺序和基本操作需要稳定。照片适合相纸与墙面，游戏适合街机，音乐适合持续播放的工作区，不能只换颜色而沿用同一套卡片。移动端还要检查宽度、动态视口、滚动和控制区域；只加 `100vh` 无法解决所有铺满屏幕的问题。

## 联机迁移尽量保留成熟规则

接入现有 HTML 游戏时，把旧 HTTP 轮询迁移为 WebSocket，并用兼容层保留游戏的调用方式。这样修改集中在房间与消息传输，规则引擎可以继续使用已有验证。Durable Objects 适合把同一房间连接集中处理，也让游戏之间的房间隔离更直接。

迁移传输协议无法消除跨境链路延迟。Cloudflare 的 APAC 提示不是大陆部署，建立持久连接后仍可能有较高 RTT。应区分首次加载、连接建立、稳定网络往返和操作反馈，台球增加 RTT 显示后才有明确的观察依据。当前对局仍由房主计算，服务端权威校验属于另一项工程。

## 图片处理应成为可重复的流程

源照片与发布图片承担不同用途。网站使用缩略图和大图两种 WebP，浏览时先加载缩略图，预览时再读大图；处理 EXIF 方向并去掉原始元数据，避免把大体积原图直接铺满网页。本机源目录放在被忽略的配置中，脚本不再绑定某台电脑的绝对路径。

图片不显示、文件从发布目录移除、文件从 Git 历史撤回是三件事。只删页面入口不能撤回已公开文件。生成脚本也不会普遍删除旧素材，更新索引后还要检查发布目录。

## 浏览器权限与云端网络要分开判断

静态网页可以发送请求，但读取跨域响应依赖目标站的 CORS 许可。`no-cors` 不能让页面读取数据，也不能突破 Cookie 的域隔离。B站 iframe 内显示已登录，不代表父页面可以获取该登录态或 Cookie。

因此音乐采用发布后的 BV 号与分P，在需要播放时由 Worker 解析音轨，再同源流式转发给 `<audio>`。前端负责队列、音量、进度和界面，MV 入口打开原视频。失效的签名地址按需刷新，不把临时播放 URL 当作长期歌单内容。

音乐封面最初预下载到仓库，歌曲增加后改为 Worker 按需获取 B站视频封面并边缘缓存。歌单只需保存资源选择和已知时长，页面懒加载，拼图由在线图片组成；避免每次更新歌曲都提交一批图片，也避免每次刷新重新查询整个歌单。

## 本地能用，仍要在云端做对照

本地 Wrangler 和线上 Worker 的出口、协议环境与上游判断不同。音乐接口出现 412 后，逐步缩小到二维码、视频详情、设备信息、WBI 与媒体请求分别测试，而不是一次更换所有请求头。

一次独立云端测试中，相同应用请求头下原生 fetch 的二维码请求返回 412，Socket 返回有效二维码；但视频详情仍失败。继续检查发现匿名详情与 WBI 请求丢弃了设备 Cookie，保留允许的 `buvid3/buvid4` 后该链路返回成功。媒体 Range 请求也单独验证了 206 与字节数。

这只能说明该次测试里哪些组合有效，不能证明 412 只有一个原因，也不能保证长期消除风控。Socket 仍从 Cloudflare 发出，不能替代真实账号与不同网络的验收。诊断应避免记录二维码轮询密钥、账号 Cookie 和带签名的媒体地址；详细范围记录在 [音乐实现](music-playback.md)。

## 音质、登录和会话需要如实表达

标题包含 Hi-res 只是选曲线索。实际音质由音源、账号权限、接口返回和浏览器解码能力共同决定，界面只展示真正可用的档位。

扫码登录获得的是网页登录会话，并非只授权音乐的 OAuth。会话虽然加密保存在访客浏览器，Worker 仍会临时解密使用，因此不能描述成服务器完全接触不到凭据。独立会话、有限有效期、同源检查和缓存隔离需要一起考虑。

## 自动部署之外，还要管理配置与数据连续性

GitHub 推送、构建成功、部署成功、域名指向当前版本是不同环节。排查更新失败时，先核对生产分支、构建命令、部署目标和版本，再看浏览器缓存。

本机 `.dev.vars`、构建变量和生产 Worker Secrets 也不相同。密钥应属于当前 Worker 的有效部署；已有会话密钥不要每次更新都重新生成，否则会让登录失效。Worker 名称、Durable Objects 绑定和迁移标签不是装饰性的项目名称，整理目录时保留它们才能延续当前部署与数据。

## 文档记录最终状态和验证边界

需求从初版游戏站发展到照片墙、留言板和音乐，早期设计与冷却规则已经不适用。README 应帮助新读者启动、部署和维护当前项目，详细实现放入专题文档。

清理文档中的个人信息不等于替换整站内容，更不等于清理历史。本轮明确保留展示内容与运行兼容标识。检查也应区分语法、模拟逻辑、运行时打包和公网实测，避免把某一项通过写成全部功能都已验证。
