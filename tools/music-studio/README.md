# 本地歌单工作室

在项目根目录运行 `npm run music:studio`，打开 http://127.0.0.1:8790 。仅监听本机。

首次启动读取根目录 `歌单.txt`，格式为每行“歌曲 - 歌手”。优先按最后一个带空格的分隔符拆分；无空格时按最后一个连字符拆分。完全重复歌曲合并，异常行数量在界面提示。

左侧选择歌曲，右侧点击“查找候选”。搜索结果按歌名、歌手、优先 UP 主、标题关键词和版本差异排序。若候选中出现优先 UP 主的名称或 UID，工具会自动锁定其中得分最高的一条；没有优先 UP 主候选时保留候选列表，等待手动锁定。人工锁定后再次搜索不覆盖。标题关键词一行一个，默认是 `Hi-res`，像 `【Hi-res】`、`无损`、`FLAC` 等标题只要包含关键词就会获得加分。当前实现对搜索返回的候选优先排序，不是遍历指定 UP 主的投稿库。

搜索不设置额外间隔或冷却，一次只执行一个联网搜索；遇到 HTTP 412、429 或业务风控码时显示错误并停止，由用户手动重试，不自动重试。上游 Retry-After 仅用于提示。已保存候选优先从本地读取，勾选“强制重新联网搜索已缓存歌曲”才重新请求。

取消工具冷却不会解除 B站自身的限制。曾参考 yt-dlp 关于设备 Cookie、请求头和 412 的讨论：[PR 16889](https://github.com/yt-dlp/yt-dlp/pull/16889)、[Issue 14830](https://github.com/yt-dlp/yt-dlp/issues/14830)。这些讨论不能证明同样的方法适用于本工具的搜索接口。本工具不收集浏览器 Cookie。

支持指定分P和视频试听。自动候选不是已确认资源，导出保留 `confirmed` 标记。

项目自动保存在被 Git 忽略的 `.music-studio/project.json`。重新导入按稳定歌曲 ID 保留已有选择；不在新文本中的歌曲移出当前项目，建议先导出备份。导出 JSON 保存当前已选资源；“更新网站歌单”写入 `public/music/playlist.json`，不自动提交或推送。

优选 UP 主名单在该文件的 `preferred` 数组；推荐在工作室中每行填写一个 UID，直接修改文件后需要重启工作室。“更新网站歌单”也会发布按 UID 区分的实时 UP 主歌单；只改名单可运行 `npm run music:playlists`，原有收藏保持不变。名单名称尽量复用已保存候选中的作者名，找不到时显示 UID。

UP 主歌单不预抓取全部投稿，也不预先统计数量。网站点击歌单才读取第一页，后续按需加载；随机播放从接口返回的总数中随机选一个位置，只读取对应页，不局限于已显示的视频。网站搜索只筛选已加载投稿，多分P视频默认播放第一P。列表页边缘缓存 10 分钟、浏览器缓存 1 分钟，刷新页面可重新读取；遇到 B站风控显示重试入口，不自动扫描或反复请求全部投稿。

网站封面由 Worker 按需读取 B站视频封面并缓存，不写入歌单或项目图片目录；发布后无需下载图片。重新发布保留同一 BV 号和分P的已知时长。播放时会读取实际时长，如需提前补齐列表信息，可选运行 `python scripts/music-metadata.py`（Python 标准库即可）。脚本顺序低频请求公开详情，遇到 412/429 立即停止，不读取账号 Cookie。喜欢和最近播放由网站访客自己的浏览器保存，与本地工作室数据无关。

网站入口为 `/music/`，在导航中排在留言板之前。发布后由 Cloudflare Worker 使用 `@bryan-kuang/bilibili-audio-extractor@0.1.0` 解析独立音轨，通过原生音频元素和自定义控件播放，MV 按钮打开 B站原视频。默认访客播放，也支持可选扫码登录，账号会话加密保存在当前浏览器，Worker 临时使用，不与其他访客共享。音质菜单只显示接口实际返回且浏览器支持的音轨，登录不能保证 Hi-Res。配置方式见根目录 README。

本地工作室仍在 8790 端口；网站完整预览使用 `npm run dev` 启动 8787 端口。静态服务不能运行 `/api/music/*`。音轨接口存在地区和风控限制，遇到 412 停止解析并提示稍后重试。
